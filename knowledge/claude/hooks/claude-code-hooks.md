# 思考

1. 本质上 它是一个 在 claude 进行实际操作时前后的预校验 不会走到 大模型 而是在 大模型调用工具的前后进行的实际的物理脚本的检查 并且检查结果是绝对明确唯一的 不会受到大模型本身能力的限制
1. config 里面的字段格式等可能会随着 claude 本身功能的演化和演进变化 所以现在的退出标志 使用 exit2 这个约定好的 exit code
1. 只有改动 config 和 config 里面的内容的时候 需要 reload window 不需要重开 session 因为 session 是网络概念 和 本地的环境又是两个不同的东西 而我们的 config 只对本地的 项目生效 当然这个的前提是 没有修改 API 供应商 修改了 API 供应商的话需要新开 session 因为 它拿不到旧的 session
1. hooks 和 skills 还不一样 hooks 是绝对结果 而 skills 实际上是将一段约束内容发给大模型 让 大模型根据 这个 skills 中的描述去做事情 所以它会收到大模型的限制 甚至可能同一个 skill 同一个模型 不同上下文里面出现的结果都是不一样的 因此建议 一些工具类的 skill 不要穿插在实际的工作内容中进行 而是单独开一个 session 来收集这个 skill 本身所需要的上下文 然后可以在它里面增加部分 scripts 来减少对大模型的调用 尤其是一些明确性结果的内容
