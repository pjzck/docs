# skills思考

1. `skills` 相当于把一些常用的工作流给总结出来 然后喂给 ai大模型 去用 最终执行效果其实非常看 ai大模型 的能力
2. 所以可以串联一些 `skills` 来完善出一个 routemap 作为 AI 去实现一个内容的方法论 当然这套方法论需要尽可能精简 否则容易出现大上下文情况下 AI 无法遵守 skills 的情况
3. ai 对 `skills` 的遵守情况并不是绝对的 所以还是需要保证经常去清理上下文防止AI幻觉
	1. 最近的新的模型和 harness 这个情况好了很多 但是对上下文的控制还是需要的
4. 有时候 `skills` 的迭代过程中 会出现新的系列 skill 可以完美达成一个旧的 `skill` 的功能 例如目前的 `skills-manage-cli` 的 `skill` 其实已经完全取代了 `vscode-cc-skill` 这个用于给 vs 创建 skill 的 skill 毕竟它本身的实际功能其实只是为了去限制 `skill` 
5. 如果制作类似于 mcp 或者其他需要使用到脚本的工具 在 skill 里面尽量提前制作好对应的 skill 的 scripts 的内容 然后 agent 在使用的时候 尽量是只去填写需要的参数 而不是需要从 环境变量开始 一步一步去逐步读取 和 测试 实际的使用方式 例如 mcp 中的 python 使用方式之类的，他可以同时提升agent的使用效率，也可以节省 agent 的使用费用 节省 token。
	1. 同理基于上面的内容来说，一般来说如果在使用过程中遇到了一些新的 case 需要及时 让 agent 进行总结一下 然后新开一个 agent 去做对 skill 的完善功能。或者这个 agent 对话可以长期保留，专门用来负责处理 skill 的相关改动
